# storefront-design-system

## هدف
هر سایت فروشگاهی بعدی از **یک** استاندارد پیروی کند: وعدهٔ روشن، محصول قهرمان، ریتم سینمایی، سه‌بعدی
با دلیل، فارسی اصیل و سبک. این مهارت منبع حقیقت طراحی را می‌خواند و همان قرارداد را روی سایت
جدید اعمال می‌کند؛ طراحی هر پروژه از صفر «حس» نمی‌شود.

## منابع canonical (همیشه اول بخوان)
- `storefronts/design-system/MASTER.md` — ستون‌ها، توکن‌ها، تایپوگرافی، کامپوننت‌های اجباری، بودجهٔ کارایی.
- `storefronts/design-system/pages/home.md` · `shop.md` · `product.md` · `content-and-contact.md`
- `storefronts/design-system/motion-3d.md` — لایه‌های ۳D، الگوهای reveal، کاهش حرکت.
- `storefronts/checklist/release-gates.md` — گیت‌های انتشار، شواهد اجباری.
- `storefronts/sites.json` — سایت‌های زنده، پالت، فونت و وضعیت گیت‌های هر برند.
- الگوی کد اجرایی: `fjcod/design-system/cham/MASTER.md` (توکن + override صفحه).

## چه زمانی فعال شود
ساخت یا بازطراحی صفحهٔ خانه/فروشگاه/محصول/سبد یک فروشگاه فارسی؛ درخواست «سایت فروشگاهی»،
«صفحهٔ محصول»، «لندینگ فروش»، «سه‌بعدی برای محصول»؛ یا بازبینی یک سایت موجود (مثل NAFAS،
NIGHTLAB، LIFESTAR) که کاربر می‌خواهد ارتقا/یکدست شود.

## گردش کار (اجباری، به ترتیب)
1. **بریف یک‌صفحه‌ای** قبل از کد: مخاطب، وعدهٔ اصلی (≤ ۹ کلمه)، سه رنگ، فونت، محصول قهرمان،
   مسیر خرید واقعی (پرداخت/دایرکت/فرم) و محدودیت‌ها. اگر داده‌ای نیست، از کاربر بپرس — حدس نزن.
2. **توکن برند** را از `MASTER.md` §۲ بساز؛ حداکثر ۳ رنگ + رنگ وضعیت. فونت‌ها self-host.
3. **اسکلت صفحات** با همان ترتیب `pages/*.md`؛ اول محتوا و لینک واقعی، بعد افکت.
4. **تجارت**: سبد localStorage، قیمت/تخفیف/آستانهٔ ارسال هم‌خوان، محصول ناموجود غیرفعال.
5. **حرکت و ۳D** فقط پس از پاس‌شدن ساختار: یک قهرمان، بودجهٔ بخش ۸، fallback استاتیک.
6. **RTL و دسترس‌پذیری**: ۳۲۰px بدون overflow، فوکوس دیده‌شده، Escape همه را می‌بندد،
   `prefers-reduced-motion`.
7. **سئو**: title/description یکتا، `Organization` + `Product`/`Offer` + `FAQPage`، sitemap.
8. **گیت‌ها** را با `node storefronts/scripts/storefront-check.mjs --dir <site>` و
   `release-gates.md` بگذران؛ نتیجهٔ واقعی را در `storefronts/PROGRESS.md` ثبت کن.
9. **انتشار** با Root Directory همان پوشه در Vercel؛ لینک زنده + تاریخ بازدید موبایل را ثبت کن.

## قواعد ثابت (نباید نقض شوند)
- **هیچ آمار، نظر یا ادعای ساختگی.** اگر داده واقعی نیست، در صفحه و در PROGRESS با «نمونه» علامت بخور.
- **هیچ لوگو/تصویر برند با کد ساخته نمی‌شود**؛ کد فقط برای چیدمان، متن فارسی روی عکس و بهینه‌سازی است.
- **سه‌بعدی تزئینی ممنوع**؛ هر افکت باید یک تصمیم خرید را ساده‌تر کند و روی reduced-motion خاموش شود.
- **هیچ کلید/توکن در کلاینت**؛ اگر به سرویس نیاز است، متغیر محیطی + تابع سرورلس.
- **یک منبع حقیقت**: تغییر استاندارد = ویرایش `storefronts/design-system/`، نه کپی محلی در پروژه.
- **محصول حساس/بزرگسال**: دروازهٔ سن، متن خنثی، بدون ذخیرهٔ داده، بدون تصویر گرافیکی در og:image.
- **تست‌نشده = تأییدنشده**: build سبز معادل انتشار زنده یا تجربهٔ موبایل واقعی نیست.

## خروجی
1. توکن و بریف برند (قابل کپی).
2. صفحه‌های ساخته/ارتقایافته با ترتیب استاندارد.
3. گزارش گیت‌ها: هر گیت ✅/⚠/✗ با دلیل و عدد.
4. ثبت در `storefronts/sites.json` و `storefronts/PROGRESS.md` (تاریخ، فایل‌ها، فرمان، نتیجه، کار باز).
